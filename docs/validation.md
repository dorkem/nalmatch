## 배포 환경 확인

- 실행 주소: [dorkem.github.io/nalmatch](https://dorkem.github.io/nalmatch/)
- 배포 원본: `main` 브랜치의 루트, `.nojekyll` 사용
- 최초 배포: [GitHub Pages 빌드 성공](https://github.com/dorkem/nalmatch/actions/runs/43715324763)
- `index.html`, CSS, JavaScript 모듈 2개, 샘플 이미지 4개의 HTTP 200 응답과 검토한 로컬 파일과의 일치 확인
- 배포 주소에서 가상 참여자 선택 → 날짜 추가 → 결과 확인 → 새로고침 → 응답 복원 수행
- 배포 페이지의 오류 로그 0개 확인

이 점검은 정적 프론트엔드 데모에 대한 것입니다. 공동 저장 서버나 카카오 API 연동의 검증 결과는 아닙니다.

## 아직 수행하지 않은 검증

사용자 인터뷰, 실제 모임의 공동 사용, 여러 기기 동기화, 접근성 보조기기 테스트, 카카오톡 공유 SDK 연동은 아직 수행하지 않았습니다.

다음 실험에서는 기존 카톡 대화와 같은 인원·조건에서 가능한 날짜를 찾는 과정을 비교합니다. 소요 시간, 날짜 선택 오류, 응답 수정 횟수, 참여자가 막힌 지점을 기록합니다.

## 공개 전 검토에서 바꾼 점

- 실제 대화에서 나온 이름과 일정을 가상 데이터로 교체
- 대화형 도구 전용 저장·디자인 제어 코드 제거
- 브라우저 전용 저장임을 화면과 README에 명시
- 이름 선택을 인증 기능으로 표현하지 않음
- ‘전원’의 기준을 등록된 참여자로 명시
- 모든 표시를 해제해도 저장할 수 있도록 수정
- 현재 월 기준 표시와 지난달 응답 정리 규칙 추가
- 측정하지 않은 사업 성과나 AI 기능을 구현 성과로 주장하지 않음
